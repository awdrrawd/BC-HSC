# 催眠儀式動畫座標系

## 結論

催眠儀式中的符咒與圓形波紋必須使用同一套座標。

符咒由 DOM 元素繪製，`_place()` 接收的是 viewport（螢幕 CSS 像素）座標：

```js
_place(talisman, cx, yHead, width, opacity);
```

因此圓形波紋也應直接以同一組 `cx, yHead` 作為 Canvas 圓心：

```js
ctx.arc(cx, yHead, radius, 0, Math.PI * 2);
```

目前的正確方案是使用固定覆蓋 viewport 的透明 Canvas，讓 Canvas 繪圖座標與符咒的 DOM 座標都是 CSS 螢幕像素。兩者不再需要互相換算。

## 為什麼這個方案有效

先前方案使用 `1000×1000` 邏輯 Canvas，再以 CSS 的 `left`、`top`、`width`、`height` 把它放到人物區。這同時存在三套座標：

1. BC 的 `2000×1000` 邏輯座標。
2. 儀式 Canvas 的 `1000×1000` 內部座標。
3. DOM 與符咒使用的 viewport CSS 像素座標。

錯誤的核心不是應該除以二或除以四，而是已經算出的符咒中心被誤用成 Canvas 左上角。接著又在 Canvas 內以 `(500,500)` 畫圓，於是圓心會額外向右、向下偏移半個 Canvas 顯示尺寸。

新方案只有一套座標：

- Canvas 固定在 viewport 的 `(0,0)`。
- Canvas 內的繪圖單位經 DPR transform 後等於 CSS 像素。
- 符咒中心是 `cx, yHead`。
- 圓心也是 `cx, yHead`。

因此不存在 Canvas 左上角、BC 邏輯座標或左半區尺寸造成的二次偏移。

## BC 左側人物區的關係

BC 主畫布是 `2000×1000`，人物畫面位於左側 `1000×1000`。這個關係仍用於：

- 決定中央人物位置。
- 根據人物區高度計算人物、符咒及圓的視覺尺寸。
- 確保圓的半徑適合人物區。

但它不再用來定位儀式 Canvas。儀式 Canvas 雖覆蓋 viewport，實際只有人物附近的透明圓形線條被繪製，不會覆蓋或攔截右側聊天室操作。

## 高 DPI 處理

Canvas backing store 依 `devicePixelRatio` 放大，CSS 尺寸仍等於 viewport：

```js
canvas.width = innerWidth * dpr;
canvas.height = innerHeight * dpr;
ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
```

如此 `ctx.arc(cx, yHead, ...)` 仍使用 CSS 像素，線條在高 DPI 螢幕上也不會模糊。

## 不應再採用的做法

- 不要用符咒中心作為 Canvas 的 `left/top`。
- 不要透過 `/2` 或 `/4` 反覆抵銷可見偏移。
- 不要先轉成 BC 座標，再轉成 Canvas 座標，最後又轉回 CSS 座標。
- 不要為了移動圓而修改人物或符咒動畫的位置。
- 不要在局部透明 Canvas 填滿矩形暗角，否則 Canvas 邊界可能可見。

## 本次變更審核

原有催眠動畫的下列行為未被改動：

- 符咒進場、停留與兩次閃光。
- 符咒由人物後方穿到前方。
- 符咒縮小並移動到頭部。
- 人物快照、淡入與淡出。
- 最後震動階段與動畫總時長。
- `done` 回呼、`stopHypnoAnim()` 與催眠狀態進入流程。

人物幾何公式曾由：

```js
cx = rect.left + rect.width * 0.25;
cy = rect.top + rect.height * 0.50;
```

改寫為：

```js
gameWidth = rect.width / 2;
cx = rect.left + gameWidth / 2;
cy = rect.top + rect.height / 2;
```

兩者數學上完全相同，不會改變人物或符咒位置。

目前相對原始動畫真正新增的內容只有：

- 一張透明 viewport Canvas。
- DPR 尺寸同步。
- 以 `cx, yHead` 為中心的四層收束圓環。
- 動畫結束前的圓環淡出。

另外，強制催眠狀態的紫色 tint 目前透明度為 `0.30`；這屬於持續催眠濾鏡調整，與儀式圓形座標無關。
